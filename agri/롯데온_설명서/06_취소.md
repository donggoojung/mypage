# 06. 취소 · 발송가능여부 (롯데온 API 센터 기준, 읽은 날짜 2026-11-05)

공통: 주소 앞부분은 `https://openapi.lotteon.com`. 클레임 API 공통 오류 표(HTTP): 200 / 401 / 404 / 429 / 403 / 500 (다른 파일과 동일).
※ 해석: 클레임(취소·반품·교환)은 `odNo`(주문번호) + `clmNo`(클레임번호) + 줄마다 `odSeq`/`procSeq`/`orglProcSeq` 조합으로 다룬다.
설명서 표의 `itemList` 하위 항목은 표에서 한 줄로 합쳐 보이는데, 요청 예시 JSON 기준으로 `itemList` 배열 안쪽 필드다.

## C. 취소요청 승인처리 (apiNo 60)
- `POST https://openapi.lotteon.com/v1/openapi/claim/v1/cancellationOpenApi/cnclRequestApproval`
- 설명: 판매자에게 취소요청이 들어온 건을 승인 처리. **"취소승인은 클레임 번호 단위로 처리됩니다. itemList는 상태 검증 및 클레임 번호 체크용으로 사용."**
- 요청
| 항목 | 필수 | 타입 | 길이 | 설명 |
|---|---|---|---|---|
| odNo | O | String | 30 | 주문번호 |
| clmNo | O | String | 30 | 클레임번호 |
| itemList | | array | | |
| itemList[].odSeq | O | Number | 3 | 주문순번 |
| itemList[].procSeq | O | Number | 3 | 처리순번 |
| itemList[].orglProcSeq | O | Number | 3 | 원처리순번 |
| itemList[].slrRsnCd | O | String | 20 | 판매자사유코드(취소). "승인시 판매사유코드는 클레임사유코드로 사용": 101~117 (A의 클레임사유 표 앞부분과 같음) |
| itemList[].slrRsnCnts | △ | String | 200 | 판매자 사유 내용 |
| itemList[].lrtrNo | △ | String | 20 | 하위거래처번호 |
- 응답: returnCode(O,4), message(String 300). 성공 `{"returnCode":"0000","message":"정상 처리 되었습니다."}`
- returnCode: 0000 / 2000 주문번호를 반드시 입력 / 2001·2002 기간조회 시작·종료일 / 2006 형식 yyyyMMddHHmmss / 3001 주문번호가 존재하지 않습니다 / 3002 주문순번이 존재하지 않습니다 / **3006 주문의 상태를 확인해 주세요** / 3009 DDB에 배송회수구분의 코드값이 없습니다 / 9000~9002
- 요청 예시(설명서 그대로, JSON 문법 오류 포함: `"slrRsnCnts","판매자사유내용"` 쉼표/콜론 혼용, 표에 없는 trNo/procDttm/procNo 포함):
```
{"odNo":"2019102210000132","clmNo":"2019102530000002","itemList":[{"odSeq":"1","procSeq":"2","slrRsnCd":"XX","slrRsnCnts","판매자사유내용","trNo":"12345","procDttm":"20191201","procNo":"20191231"}]}
```
- ※ 해석: 설명서의 승인 사유코드는 표에 101~117이 있고 예시는 "XX"라서, 고객 변심 취소 승인 시 고객이 낸 clmRsnCd 값을 그대로 slrRsnCd에 넣는 방식이 안전해 보임(설명서에 명시는 없음).
- ※ 해석: 발송완료 통보(상태 13) 이후에는 취소 승인이 아니라 반품 흐름으로 가는 것으로 보이나, 설명서에 이를 직접 설명한 문장은 없음.

## D. 취소요청 거부처리 (apiNo 59)
- `POST https://openapi.lotteon.com/v1/openapi/claim/v1/cancellationOpenApi/cnclRequestHold`
- 요청: odNo(O,30), clmNo(O,30), itemList[]{ odSeq(O), procSeq(O), orglProcSeq(O), slrRsnCd(O, String 20, 판매자 사유 코드), slrRsnCnts(△,200), lrtrNo(△,20) }
- slrRsnCd(거부): `901` 이미 상품을 발송함 / `902` 고객과 협의 후 취소거부 / `903` 취소가 어려운 상품(주문제작상품 등)
- 응답: returnCode, message. 오류: 2000, 2001, 2002, 2006, 2007, 3001, 3002, **3006 주문의 상태를 확인해 주세요**, 9000~9002
- 요청 예시는 C와 같은 형식(slrRsnCd "XX"로 표기).
- 이름은 "거부처리"이지만 주소 끝이 `cnclRequestHold`(보류) 임. 취소요청(완료)조회의 excpProcDvsCd(예외처리구분) 값은 03 보류 / 04 거부.

## E. 판매자직접취소 (apiNo 225) — 품절 등으로 우리가 먼저 취소

- 설명: 판매자에게 직접취소 처리를 제공.
- 요청
| 항목 | 필수 | 타입 | 길이 | 설명 |
|---|---|---|---|---|
| odNo | O | String | 30 | 주문번호 |
| itemList | | array | | |
| itemList[].odSeq | O | Number | 3 | 주문순번 |
| itemList[].procSeq | O | Number | 3 | 처리순번 — "(취소하고자 하는 원 주문의 처리순번으로 요청 필요)" |
| itemList[].slrRsnCd | O | String | 20 | 판매자사유코드(취소). "판매사유코드는 클레임사유코드로 사용": `111` 판매자 취소(품절) / `132` 가격오등록 / `133` 리셀러주문 / `137` 택배지원불가 (22.08.23 추가) / `135` 판매자 취소(고객변심) (22.11.29 추가) |
| itemList[].slrRsnCnts | △ | String | 200 | 판매자 사유 내용 |
| itemList[].lrtrNo | △ | String | 20 | 하위거래처번호 |
- 응답: returnCode(O,4), message(O,300). 성공 `{"returnCode":"0000","message":"정상 처리 되었습니다."}`
- returnCode: 0000 / 2000 주문번호를 반드시 입력 / 3001 주문번호가 존재하지 않습니다 / 3002 주문순번이 존재하지 않습니다 / 3003 처리순번이 존재하지 않습니다 / **3010 추가결제금액이 존재하여 접수(요청)를 진행할 수 없습니다** / 3018 판매자 사유코드가 존재 하지 않습니다 / 9000~9002
