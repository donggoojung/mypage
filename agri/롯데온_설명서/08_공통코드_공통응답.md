# 08. 시작하기(공통 규칙) · 공통코드 · Identity · 공통 응답 (롯데온 API 센터 기준, 읽은 날짜 2026-11-05)

---
## A. 시작하기 (개요) — 설명서 `?apiNm=GetStarted`
- 호출 도메인: `https://openapi.lotteon.com`. Restful, **Method는 GET/POST만 지원**. 통신은 HTTPS. json과 xml 규격 제공.
- OpenAPI Key 발급: 판매자 센터 > 판매자정보 > OpenAPI관리. **상위거래처 기준으로만 발급, 교체 발급용으로 최대 3개**까지 발급 가능. 하위거래처 단위 연동이 필요한 API는 문서별로 추가 파라미터(lrtrNo 등)를 요구.
- 인증 단계 2가지:
  1. 인증키 체크 — 키가 잘못 설정됐거나 만료되면 **401**.
  2. **출발지 IP 주소 체크** — 인증키에 등록된 출발지 IP만 허용(여러 개 입력 가능). 아니면 **403**. ※ 해석: 서버/PC의 공인 IP를 판매자센터 OpenAPI관리에 미리 등록해야 호출됨.
- 접속량 제어: 인증키별 **분당 10,000회**. 초과 시 **429**. (각 API 표의 429 문구는 "00분 후 다시 호출"/"1분 후 다시 호출" 등 다양, 발송가능여부체크 208은 returnCode 1004 "하루 호출 가능 회수를 초과했습니다")
- 헤더:
| 헤더 | 값 | 설명 |
|---|---|---|
| Authorization | Bearer 인증키 | 판매자 센터에서 발급받은 인증키 |
| Accept | application/json | application/json 과 application/xml 지원 |
| Accept-Language | ko | 국내 접속일 경우 ko |
| X-Timezone | GMT+09:00 | 시간 표현식의 기준 시간대. 국내는 GMT+9시 |
| Content-Type | application/json | POST 호출 시 필수, body 구성도 필수 |
- "인증키로 접속하면 상위 거래처 정보를 가지고 있으므로 따로 거래처 정보를 파라미터에 넣지 않아도 됨(하위거래처 사용시 예외)" — 단, 상품 등록 등 각 API 표에는 trGrpCd/trNo가 필수(O)로 적혀 있음. ※ 해석: 표대로 넣는 것이 안전. 값은 Identity API(C)로 확인.
- 호출 예제(java)의 성공 응답 예시: `{"returnCode":"SUCCESS","message":null,"subMessages":null,"dataCount":null,"data":""}` — 실패는 `40X`. (※ 개별 API 문서의 성공 returnCode는 `"0000"`. 시작하기 예시는 `"SUCCESS"`로 다름. 설명서 내 불일치.)
- 설명서 안에 별도의 "오류 응답 형식" 장은 없음. 각 API 문서의 6~8번(Status/Return/Result Message) 표를 따름.

## B. 공통 응답 형식 (API 문서들에서 읽은 공통 패턴)
- 최상위: `returnCode`(String, "0000" 정상), `message`, `subMessages`(null 또는 배열), `dataCount`(숫자 또는 null), `data`(배열 또는 객체 또는 null).
- 그룹별로 `data` 안이 다름:
  - 상품 API(등록·수정·재고·가격·상태변경): `data[]` 각 건마다 `resultCode`/`resultMessage`. **returnCode가 0000이어도 건별 resultCode를 확인**해야 함 (ex. 재고/가격: 건별 `resultCode:"0000"`).
  - 배송 API(통보류): `data.rsltCd` / `data.rsltMsg` (V2는 `data.failList[]`).
  - 클레임 API: returnCode / message만.
  - 거래처 등록 API(출고지·배송비정책): `data: null`, 번호 반환 없음.
  - 속성(카테고리/브랜드) API(onpick-api): `itemList[]` 형태 (`returnCode` 없음).
- HTTP 상태 표(모든 문서 공통): 200 정상(체크에서 에러값은 리턴코드로 출력) / 401 등록되지 않은 OpenAPI Key / 404 비정상 Request 호출·페이지 없음 / 429 호출 가능 횟수 초과 / 403 접근 거부 / 500 시스템 오류.
- 흔한 returnCode/resultCode (상품 계열): 0000 정상 / 9999 SYSTEM ERROR / 1001 [해당항목]은 필수입력 / 1002 [해당항목]의 DATA형식이 잘못 / 1003 [해당항목]의 공통코드가 잘못 / 2001 업무영역(예: 종료일이 시작일보다 이전)
- 흔한 returnCode (배송·클레임 계열): 0000 / 2000 잘못된 파라미터(코드값) / 2001 필수값 누락 / 2002 데이터(타입,사이즈) 오류 / 2003 조회기간은 1일을 초과할 수 없습니다 / 2004 잘못된 OpenAPI 서비스 코드 / 2008 저장할 자료가 없습니다 / 3xxx 업무영역 / 9000 예상치 않은 오류 / 9001 데이터베이스 오류 / 9002 시스템 내부 오류
- 공통코드 계열: 0000 / 2000 [그룹코드]는 반드시 입력해 주세요 / 3000 처리중 오류가 발생하였습니다.

## C. OpenAPI 토큰 Identity 조회 (apiNo 207) — 내 거래처번호 확인
- `GET https://openapi.lotteon.com/v1/openapi/common/v1/identity` (설명서에는 `/v1/openapi/common/v1/identity` 경로만 표기)
- 요청 파라미터: 없음.
- 응답: returnCode(O, String 4), message(String 200), subMessages(Array), dataCount(Integer), `data`(O, Object):
| 항목 | 필수 | 타입 | 길이 | 설명 |
|---|---|---|---|---|
| data.trGrpCd | O | String | 50 | 거래처 그룹코드 |
| data.trDvsCd | O | String | 50 | 거래처 구분코드 |
| data.trNo | O | String | 200 | 거래처번호 |
| data.trNm | O | String | 200 | 거래처이름 |
- 응답 예시: `{"returnCode":"0000","message":"The request has been processed at 2023-04-14T12:32:34.002.","subMessages":null,"dataCount":null,"data":{"trGrpCd":"SR","trDvsCd":"SR","trNo":"LO00001","trNm":"롯데닷컴"}}`
- 오류: 0000 / 3000 요청공통 처리중 오류가 발생하였습니다. HTTP 429는 "1분 후 다시 호출".
- 용도(※ 해석): 연결 테스트(키·IP 확인) 겸 trGrpCd/trNo 값 확보. 읽기 전용이라 안전하게 첫 호출로 쓰기 좋음.

## D. 공통코드 그룹조회 (apiNo 88)
- `GET https://openapi.lotteon.com/v1/openapi/bocommon/v1/code/getGroupCodeList` (설명서 표기 `/v1/openapi/bocommon/v1/code/getGroupCodeList`)
- 설명: 그룹코드의 목록을 조회. (설명서 첫 줄: "그룹코드를 파라미터로 상세그룹코드 목록을 조회할 수 있습니다" — 실제 파라미터는 없음. 상세는 E 사용)
- 요청 파라미터: 없음.
- 응답: returnCode(O,4), message(200), subMessages, dataCount(O), data[]{ grpCd(O,50 그룹코드), grpCdNm(O,50 그룹코드명), grpCdEpn(200 그룹코드 설명) }
- 응답 예시: `{"returnCode":"0000","message":null,"subMessages":null,"dataCount":150,"data":[{"grpCd":"ACCM_VP_KND_CD","grpCdNm":"적립시점종류코드","grpCdEpn":""},{"grpCd":"ACCP_DVS_CD","grpCdNm":"TNS접수구분","grpCdEpn":""},...]}` (그룹 150개)
- 오류: 0000 / 3000. 429는 "1분 후 다시 호출".

## E. 공통코드 상세조회 (apiNo 89)
- `GET https://openapi.lotteon.com/v1/openapi/bocommon/v1/code/getDetailCodeList?grpCd=<그룹코드>&langCd=ko`
- 요청: grpCd(O, String 50, 그룹코드), langCd(String 20, 언어코드 default ko)
- 응답: returnCode(O), message, subMessages, dataCount(O), data[]{ grpCd(O), langCd(O), cd(O, 50 코드), cdNm(O, 50 코드명), cdEpn(200 코드설명), sortSeq(Integer), refcChrValEpn1~4(100 참조문자값설명1~4) }
- 응답 예시: `{"returnCode":"0000","dataCount":16,"data":[{"grpCd":"HOLI_DD_CD","langCd":"ko","cd":"HLDY01","cdNm":"신정","cdEpn":"","sortSeq":"3","refcChrValEpn1":"","refcChrValEpn2":"","refcChrValEpn3":"","refcChrValEpn4":""}, ...]}`
- 오류: 0000 / 2000 [그룹코드]는 반드시 입력해 주세요. / 3000 처리중 오류가 발생하였습니다. 다시 시도해주세요.
- 상품 등록 설명서가 가리키는 공통코드 그룹명(grpCd로 쓸 값): MALL_DVS_CD, SL_TYP_CD, PD_TYP_CD, GFTV_SHP_CD, OPLC_CD(원산지), TDF_DVS_CD, PD_ITMS_CD(품목고시), IMP_PRX_CD, SFTY_ATHN_TYP_CD, ITYP_OPT_DVS_CD, MAX_PUR_LMT_TYP_CD, AGE_LMT_CD, IMP_DVS_CD, CTRT_TYP_CD, PD_STAT_CD, FILE_TYP_CD, FILE_DVS_CD, PD_EPN_TYP_CD, DMST_OVS_DV_DVS_CD, DV_PROC_TYP_CD, DV_PD_TYP_CD, DV_RGSPR_GRP_CD(배송가능지역), DV_MNS_CD, DV_CO_CD(택배사), SAVE_TYP_CD, RTRV_TYP_CD, EPSR_TYP_CD, EPSR_TYP_DTL_CD, SL_STAT_CD, SL_STAT_RSN_CD, PD_APRV_REQ_CD, CAT_APRV_STAT_CD, PD_INFO_APRV_STAT_CD, QST_TYP_CD, QNA_STAT_CD, ITM_DC_TYP_CD, PY_MNS_CD
- ※ 해석: **원산지(OPLC_CD)와 배송가능지역(DV_RGSPR_GRP_CD)의 실제 값은 이 설명서에 없고, 이 API로 받아야 함.** 품목고시 항목코드(pdArtlCd) 목록의 그룹이 공통코드에 있는지는 설명서에 안 나옴 — 그룹 목록(D)에서 이름을 검색해 보아야 함.
- 설명서 속 공통코드 값 표는 본 폴더 각 파일에 해당 API 옆에 옮겨 놓았음.

## F. 읽지 않은 항목
- 설명서 메뉴에는 위 외에도 "기준 휴일 조회", "휴일 정보 등록 관리", "휴일 조회", "휴일 제외등록"(공통 메뉴)이 있으나 범위 밖이라 읽지 않음. ※ 해석: 농산물 발송예정일 계산에 휴일 정보가 연관될 수 있음.
