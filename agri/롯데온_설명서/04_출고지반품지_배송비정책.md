# 04. 판매자 출고지/반품지 · 배송비정책 (롯데온 API 센터 기준, 읽은 날짜 2026-11-05)

공통: `https://openapi.lotteon.com` + POST + JSON. 이 그룹은 "거래처(contract)" API라서 상품 API와 달리 거래처 코드를 `afflTrCd`(상위거래처번호), `afflLrtrCd`(하위거래처번호)로 부른다.
공통 오류 표: 200 정상 / 401 등록되지 않은 OpenAPI Key / 404 비정상 Request·페이지 없음 / 429 호출 가능 횟수 초과, **1분 후** 다시 호출 / 403 접근 거부 / 500 시스템 오류.
returnCode 표: 0000 정상 처리되었습니다. / 2000 체크공통:에러메세지 안내 / 2001 권한이 없는 거래처 정보 입니다. / 2002~2009 각 필수항목 누락 메시지 / INVALID_INPUT 입력값이 유효하지 않습니다(subMessages 확인).
※ 해석: afflTrCd 값은 상품 API의 trNo와 같은 거래처번호(예시 "LO000020" 형태)로 보임. 설명서가 명시하지는 않음. Identity API(08번 파일)로 trNo를 확인할 수 있음.

---
## A. 판매자 출고지/반품지 등록 (apiNo 151)
- `POST https://openapi.lotteon.com/v1/openapi/contract/v1/dvp/registDvpSr`
- **요청 본문은 최상위가 배열 `[ {...}, {...} ]`** (예시 기준; 여러 건 한 번에).
| 항목 | 필수 | 타입 | 길이 | 설명 |
|---|---|---|---|---|
| dvpTypCd | O | String | 2 | 배송지유형코드 [회수지:`01`, 출고지:`02`] |
| dvpNm | O | String | 100 | 배송지명 |
| zipNo | | String | 7 | 우편번호 (없는 경우 '99999') |
| zipAddr | | String | 200 | 우편주소 (없는 경우 '없음') |
| dtlAddr | | String | 200 | 상세주소 (없는 경우 '-') |
| stnmZipNo | | String | 6 | 도로명우편번호 (없는 경우 '99999') |
| stnmZipAddr | | String | 200 | 도로명우편주소 (없는 경우 '없음') |
| stnmDtlAddr | | String | 200 | 도로명상세주소 (없는 경우 '-') |
| rpbtrNm | | String | 100 | 담당자명 |
| mphnNatnNoCd | | String | 20 | 휴대폰국가코드 [default '82'] |
| mphnNo | | String | 15 | 휴대폰번호 |
| telNatnNoCd | | String | 20 | 연락처국가코드 [default '82'] |
| telNo | | String | 20 | 연락처 |
| afflTrCd | O | String | 18 | 상위거래처번호 |
| afflLrtrCd | | String | 18 | 하위거래처번호 |
(예시 JSON에는 표에 없는 `useYn:"Y"`가 있고 afflTrCd는 예시에 없음.)
- 응답: returnCode(O,4), message(O,1000), subMessages(Array), dataCount(O), data(Object). 예시: `{"returnCode":"0000","message":"정상 처리되었습니다.","subMessages":null,"dataCount":2,"data":null}`
- **주의: 응답에 새로 만든 배송지번호가 안 나옴(data: null).** 상품 등록에 쓰는 `owhpNo`(출고지번호)/`rtrpNo`(회수지번호)는 아래 B(리스트 조회)로 받아야 함. (※ 해석)
- 요청 예시(첫 건):
```json
[{"dvpTypCd":"01","dvpNm":"회사","zipNo":"135-650","zipAddr":"서울시 서초구 서운로 7","dtlAddr":"신동아빌딩 7,9층 (서초동, 1255-19)","stnmZipNo":"06236","stnmZipAddr":"서울시 서초구 서운로 7","stnmDtlAddr":"신동아빌딩 7,9층 (서초동, 1255-19)","rpbtrNm":"홍길동","mphnNatnNoCd":"82","mphnNo":"1234-5678","telNatnNoCd":"82","telNo":"2473-6973","useYn":"Y"}]
```

## B. 판매자 출고지/반품지 리스트 조회 (apiNo 150)
- `POST https://openapi.lotteon.com/v1/openapi/contract/v1/dvp/getDvpListSr`
- 요청: afflTrCd(O, String 18, 상위거래처번호), afflLrtrCd(String 17, 하위거래처번호). 예시 `{"afflTrCd":"LO999999","afflLrtrCd":"SLO99999"}`
- 응답: returnCode, message, subMessages, dataCount, data[] 각 항목:
| 항목 | 타입 | 길이 | 설명 |
|---|---|---|---|
| dvpNo | String | 11 | 설명서 표기 "'PLE&PLE'+배송지번호" (예시 값 "PLO00008"). **이 값이 상품 등록의 owhpNo/rtrpNo에 들어가는 번호로 보임 (※ 해석)** |
| dvpTypCd | String | 1 | 배송지유형코드 [회수지:01, 출고지:02] |
| dvpNm | String | 100 | 배송지명 |
| zipNo / zipAddr / dtlAddr | String | 7/200/200 | 우편번호/주소/상세주소 |
| stnmZipNo / stnmZipAddr / stnmDtlAddr | String | 6/200/200 | 도로명 우편번호/주소/상세주소 |
| rpbtrNm | String | 100 | 담당자명 |
| mphnNatnNoCd, mphnNo | String | 20 | 휴대폰국가코드, 번호 |
| telNatnBoCd(설명서 표기 그대로; 예시 JSON은 telNatnNoCd), telNo | String | 20 | 연락처국가코드, 연락처 |
| lrtrNo | String | 20 | 하위거래처번호 |
| useYn | String | 1 | 사용여부 [default 'Y'] |
| rprtYn | String | 1 | 대표 출고/회수지 여부 [default 'N'] |
- ※ 해석: 출고지(02)와 회수지(01)가 같은 목록에 섞여 나오므로 dvpTypCd로 구분해서 owhpNo(출고지)와 rtrpNo(회수지)를 각각 고른다. 설명서 예시 값은 둘 다 dvpTypCd "01"이라 헷갈릴 수 있음(예시 오류로 보임).

(판매자 출고지/반품지 수정 152, 삭제 153은 이번 범위 밖이라 읽지 않음.)

## C. 판매자 배송비정책 등록 (apiNo 168)
- `POST https://openapi.lotteon.com/v1/openapi/contract/v1/dvl/registDvCstSr`
- 요청 본문도 **최상위 배열 `[ {...} ]`**.
| 항목 | 필수 | 타입 | 길이 | 설명 / 가능한 값 |
|---|---|---|---|---|
| aplyStrtDt | O | String | 8 | 적용시작일자 (YYYYMMDD, 예 20200327) |
| aplyEndDt | O | String | 8 | 적용종료일자 (예 99991231) |
| dvCstPolNm | | String | 100 | 배송지정책명 "자동 생성" (직접 안 넣어도 됨) |
| ctrtTypCd | O | String | 20 | 계약유형코드 [중계:`A`, 위탁:`B`, 판매분매입:`C`, 직매입:`D`] |
| dvTypCd | O | String | 20 | 배송유형코드 [직접배송:`DRECT`] 직접배송 default |
| dvProcTypCd | O | String | 20 | 배송처리유형코드 [업체배송:`LO_ENTP`] 업체배송 default |
| dvCstTypCd | O | String | 20 | 배송비유형코드 [배송비:`DV_CST`, 추가배송비:`ADTN_DV_CST`] |
| dvCstDvsCd | O | String | 20 | 배송비구분코드 [유료:`A`, 무료:`B`, 조건부:`C`] (추가배송비일 때는 조건부 선택 불가) |
| dvCst | | Integer | 22,2 | 배송비 (예 "2500.00") |
| rcst | | Integer | 22,2 | 반품비 |
| rtngXchgDvCstImpsMthdCd | | String | 20 | 반품교환배송비부과방법코드 [default 'N'] (예시 'Y'; 값 의미 설명서에 없음) |
| cndlFreeStdAmt | | Integer | 22,2 | 조건부무료기준금액 (배송비유형이 '배송비'인 경우 필수) |
| inrmAdtnDvCst | | Integer | 22,2 | 도서산간추가배송비 (배송비유형이 '추가배송비'인 경우 필수) |
| jejuAdtnDvCst | | Integer | 22,2 | 제주도추가배송비 (추가배송비인 경우 필수) |
| afflTrCd | O | String | 20 | 상위거래처번호 |
| afflLrtrCd | | String | 20 | 하위거래처번호 |
| useYn | O | String | 1 | 사용여부 [default 'Y'] |
- 응답: `{"returnCode":"0000","message":"정상 처리되었습니다.","subMessages":null,"dataCount":1,"data":null}` — **정책번호가 응답에 안 나옴.** 번호는 아래 D에서 조회.
- returnCode: 2002 적용시작일자 / 2003 적용종료일자 / 2004 상위거래처코드 / 2005 사용여부 / 2007 계약유형코드 / 2008 배송비유형코드 / 2009 배송비구분코드 필수입력 (2006은 "-")
- 요청 예시:
```json
[{"aplyStrtDt":"20200327","aplyEndDt":"99991231","ctrtTypCd":"A","dvTypCd":"DRECT","dvProcTypCd":"LO_ENTP","dvCstTypCd":"DV_CST","dvCstDvsCd":"A","dvCst":"2500.00","rcst":"2500.00","rtngXchgDvCstImpsMthdCd":"Y","cndlFreeStdAmt":"30000.00","inrmAdtnDvCst":"30000.00","jejuAdtnDvCst":"30000.00","afflTrCd":"LO000020","afflLrtrCd":"SLO30292","useYn":"Y"}]
```
- 주의: 상품 등록(01번)에서 신규 배송비정책은 등록 후 약 5분 지연되므로 5분 뒤에 상품에 연결.
- ※ 해석: 배송비 구분 A(유료)면 dvCst를, C(조건부)면 dvCst + cndlFreeStdAmt를 쓰는 구조로 보임. 설명서에 필수 조합표는 없음. 추가배송비(도서산간·제주)는 dvCstTypCd=`ADTN_DV_CST`로 **별도 정책을 따로 등록**하고, 상품 등록 시 adtnDvCstPolNo에 넣는 구조.

## D. 판매자 배송비정책 리스트조회 (apiNo 166)
- `POST https://openapi.lotteon.com/v1/openapi/contract/v1/dvl/getDvCstListSr`
- 요청: afflTrCd(O, String 18), afflLrtrCd(String 17). 예시 `{"afflTrCd":"LO999999","afflLrtrCd":"SLO99999"}`
- 응답 data[] 항목: dvCstPolNo(String 30, **배송비정책번호 = 상품 등록의 dvCstPolNo / adtnDvCstPolNo**), aplyStrtDt, aplyEndDt, dvCstPolNm(100), ctrtTypCd [A/B/C/D], dvTypCd [DRECT], dvProcTypCd [LO_ENTP], dvCstTypCd [DV_CST/ADTN_DV_CST], dvCstDvsCd [A유료/B무료/C조건부], dvCst, rcst, rtngXchgDvCstImpsMthdCd, cndlFreeStdAmt, inrmAdtnDvCst, jejuAdtnDvCst, trNo(상위거래처번호), lrtrNo(하위거래처번호), useYn [default 'Y'], rprtYn(대표배송정책여부 [default 'N'])
- 응답 예시 첫 건: `{"dvCstPolNo":"DLD00008","aplyStrtDt":"20200101","aplyEndDt":"20200101","dvCstPolNm":"롯데택배","ctrtTypCd":"A","dvTypCd":"DRECT","dvProcTypCd":"EC_ENTP","dvCstTypCd":"DV_CST","dvCstDvsCd":"A","dvCst":"2500.00","rcst":"2500.00","rtngXchgDvCstImpsMthdCd":"Y","cndlFreeStdAmt":"30000.00","inrmAdtnDvCst":"30000.00","jejuAdtnDvCst":"30000.00","trNo":"LO9998","lrtrNo":"SLO99998","useYn":"Y","rprtYn":"Y"}` (예시의 dvProcTypCd가 "EC_ENTP"로 나오는데 표에는 LO_ENTP — 설명서 불일치)
- ※ 해석: 상품 등록 예시의 dvCstPolNo는 "335"처럼 숫자, 이 조회 예시는 "DLD00008" 형태로 서로 다름. 실제 값은 호출해 봐야 확정.
- 수정(169)·삭제(170) API는 존재하나 이번 범위 밖이라 읽지 않음.
