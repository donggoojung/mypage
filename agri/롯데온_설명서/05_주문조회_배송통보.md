# 05. 주문 조회 · 배송(송장) 통보 (롯데온 API 센터 기준, 읽은 날짜 2026-11-05)

공통: `https://openapi.lotteon.com/v1/openapi/delivery/...` + POST + JSON. 이 그룹은 응답 형태가 두 가지: 최상위 returnCode/message에 더해 `data.rsltCd / data.rsltMsg` 가 오는 API와, 목록이 `deliveryOrderList` 로 바로 오는 API가 있다 (아래 각각 기재).
HTTP 오류 표 공통: 200 정상 / 401 등록되지 않은 OpenAPI Key / 404 / 429 호출 가능 횟수 초과, 00분 후 다시 호출 / 403 / 500.
※ 해석: 롯데온 주문의 최소 단위 키는 `odNo`(주문번호) + `odSeq`(주문순번, 단품별) + `procSeq`(처리순번, 최초 1, 클레임 발생 시 1씩 증가). 이후 모든 통보에서 이 3개 조합을 계속 보낸다.

주문진행단계코드(odPrgsStepCd) 전체 (롯데ON배송상태 조회 140 기준): 11 출고지시 / 12 상품준비 / 13 발송완료 / 14 배송완료 / 15 수취완료 / 21 취소완료 / 22 철회 / 23 회수지시 / 24 회수진행 / 25 회수완료 / 26 회수확정 / 27 반품완료. (장기 미처리 272 표에는 추가로 03 접수 / 05 주문완료)

## A. 출고/회수지시(주문정보) 조회 (apiNo 209) — 새 주문 가져오기
- `POST https://openapi.lotteon.com/v1/openapi/delivery/v1/SellerDeliveryOrdersSearch`
- 설명서 핵심 문장:
  1. 셀러는 출고지시/회수지시 주문정보를 조회해 셀러 내부 주문정보를 만든다.
  2. 내부 주문 생성 후 반드시 "출고/회수지시 연동완료 통보"(B)를 호출한다. (통보하면 상품준비중/회수진행으로 자동 변경)
  3. 주문진행상태가 출고지시/회수지시인 경우 **즉시 주문취소·회수철회가 될 수 있으므로** 수신 후 연동완료 통보를 필히 수행.
  4. 이후 상품준비 등으로 상태가 바뀌어도 이 API에서는 "출고/회수지시" 상태로 조회됨. 연동완료 이후 상태 확인은 롯데ON 배송상태 조회 API(D)를 사용.
  5. 할인금액·배송비·실결제금액은 고객 최초 결제기준 정보. 취소 주문 정보는 클레임 정보에서 확인. 실결제금액 내 배송비 할인 금액은 제외되어 있음.
  6. 지번주소는 20/05/13부터 제외(도로명주소 기준).

## B. 출고/회수지시 연동완료 통보 (apiNo 210)
- `POST https://openapi.lotteon.com/v1/openapi/delivery/v1/SellerIfCompleteInform`
- 설명서 핵심:
  - 수신한 출고지시/회수지시에 대해 **필히** 이 API로 결과를 전송.
  - `ifCplYN="Y"`로 보낸 주문은 롯데ON에서 **'자동 즉시취소'가 불가**하도록 설정됨. (자동 즉시취소 = 주문 후 고객 취소접수 즉시 취소됨 / 수동 취소승인 = 셀러가 취소요청을 직접 승인)
  - 2022.8.2부터 출고지시 주문에 Y 수신 시 주문진행상태가 **상품준비(12)**로 변경. 2023.3.30부터 회수지시 주문에 Y 수신 시 **회수진행(24)**으로 변경 (자동회수 상품 제외).
  - 반품/교환 접수 후 회수지시 단계에서도 즉시 철회(회수취소)가 가능하므로, 회수지시 수신 후 연동완료 통보를 꼭 해서 수거 중 회수취소가 안 나게 관리.

| dvRtrvDvsCd | O | string | 20 | DV 배송 / RTRV 회수 |

## C. 배송상태 통보 — 송장 입력 · 상태 변경 (apiNo 137 = V1, apiNo 298 = V2)
### 공통 설명서 문구
- 셀러가 롯데온에 주문진행 상태값을 전달. 전달값 기준으로 롯데온 주문 상태가 바뀌고, 단계에 따라 고객 알림이 발송되거나 환불 가능 기준값으로 쓰임.
- **주문진행 단계를 일정 기간 업데이트하지 않으면 발송지연, 주문취소, 회수환불 처리될 수 있음.**
- **발송완료 처리 전에 (클레임 API) "발송가능여부" 사전 체크 후 상태 변경.** 연동 시점 차로 이미 취소된 주문일 수 있음. 취소된 주문이거나 처리가능 수량보다 많은 수량으로 발송완료 업데이트하면 실패.
- 규칙에 맞지 않는 값은 에러 리턴 + 업데이트 실패. **실패한 주문을 같은 내용으로 계속 보내면 해당 IP에 수신차단 정책이 적용될 수 있음.**
- 허용되는 주문진행단계코드(odPrgsStepCd): 배송(DV) = `12` 상품준비 / `13` 발송완료 / `14` 배송완료. 회수(RTRV) = `24` 회수진행 / `25` 회수완료 / `26` 회수확정. (25/08/07 시행: DV에 24~26, RTRV에 12~14를 쓰면 3024 오류)
